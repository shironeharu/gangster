# 갱스터 패밀리 관리

## 입장 및 권한
- **뷰어 (패밀리원)**: 공용 비밀번호로 팸원 목록·상세 정보·경고 기록·사진을 조회합니다. 검색과 정렬은 가능하며 추가·수정·삭제는 불가능합니다. 면접관리와 계정 관리는 보이지 않습니다.
- **관리자 로그인**: 이름과 기존 비밀번호로 로그인합니다. 면접관리, 팸원 편집과 계정 관리가 가능합니다.
- **계정 관리 → 패밀리원 공용 비밀번호**: 관리자가 공용 비밀번호를 설정·변경합니다. 미설정 상태에서는 뷰어 입장이 거절됩니다. 변경 시 이전 비밀번호의 세션은 권한을 잃습니다.
- 새로고침 후에는 비밀번호를 다시 입력합니다.

## 기존 사이트에 적용하기 (필수)
1. Firebase 콘솔에서 기존 `admins` 문서에 관리자 비밀번호가 설정되어 있는지 확인합니다. 기존 비밀번호는 유지됩니다. 최초 설치라면 `admins/하루` 등의 문서를 만들고 `password` 문자열을 4자 이상으로 설정합니다.
2. Firebase Authentication의 익명 로그인을 활성화합니다. 프로젝트 설정은 `firebase-config.js`를 사용합니다.
3. **Firestore Database → 규칙**을 이 저장소의 `firestore.rules` 전체 내용으로 교체하고 게시합니다. 기존 전체 허용 규칙과 함께 추가하면 보호되지 않습니다.
4. 변경한 `index.html`, `app.js`, `style.css`를 GitHub Pages에 배포합니다. 규칙을 먼저 적용하는 동안 기존 화면의 로그인은 일시적으로 동작하지 않을 수 있습니다.
5. 관리자로 로그인하고 **계정 관리**에서 공용 비밀번호를 설정합니다. 사이트 링크와 비밀번호를 패밀리원에게 안내합니다.

CLI로 규칙을 배포하려면 인증 후 아래 명령을 사용합니다.

```sh
npx firebase deploy --only firestore:rules --project shironeharu-d17d0
```

**화면 파일만 업로드하면 권한 보호가 적용되지 않습니다. 보안 규칙 게시까지 완료해야 합니다.**

## 관리자 계정
관리자 이름은 윙윙, 절미, 하루, 떵구입니다. 누구나 최초 비밀번호를 등록하던 동작은 제거했습니다. 계정 관리에서 등록된 관리자의 비밀번호를 재설정할 수 있습니다. 미등록 계정은 Firebase 콘솔에서 생성합니다. 자신의 비밀번호를 변경한 경우 다시 로그인합니다.

면접자와 팸원은 관리자가 추가·수정·삭제합니다. 2차 면접 담당자는 떵구로 고정이며, 기존 2차 기록 편집 제한은 화면에서 적용됩니다. 사진은 압축 후 Firestore 문서에 저장합니다.

## 권한 구현
익명 Firebase UID마다 `accessSessions/{uid}` 문서를 사용합니다. 로그인 요청의 역할·이름·비밀번호를 Firestore 규칙이 관리자 문서 또는 공용 비밀번호와 대조합니다. 모든 데이터 요청에서 현재 비밀번호를 검증합니다. 뷰어는 `members` 읽기만 허용되며 면접·관리자·설정 조회와 데이터 쓰기는 서버에서 거절됩니다. 세션 문서는 클라이언트에서 읽을 수 없습니다.

기존 비밀번호 확인 기능과 호환하기 위해 비밀번호는 Firestore에 평문으로 저장되며 관리자와 프로젝트 운영자는 접근할 수 있습니다. 로그인 시도 횟수 제한은 구현되어 있지 않습니다. 충분히 길고 다른 서비스와 중복되지 않는 비밀번호를 사용하세요.

## 검증
Node.js와 Java 21 이상이 필요합니다. 운영 데이터 대신 로컬 에뮬레이터를 사용합니다.

```sh
npm ci
npm test
npm run test:rules
```

UI 테스트는 뷰어 화면, 수정 이벤트 차단, 로그아웃과 관리자 전환을 확인합니다. 규칙 테스트는 비밀번호 검증, 뷰어 읽기 전용, 면접·비밀번호 접근 차단, 권한 위조, 비밀번호 변경과 로그아웃 후 접근 거절을 확인합니다.
