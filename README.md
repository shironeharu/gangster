# 갱스터 패밀리 관리 사이트

관리자(윙윙, 절미, 하루, 떵구)가 함께 사용하는 면접자/팸원 관리 사이트입니다.
GitHub Pages로 배포하고, 데이터 저장은 Firebase(Firestore)를 사용합니다.
상단에 **면접관리** / **팸원관리** 두 개의 탭이 있습니다.

## 면접관리 탭
닉네임 / ID / 면접일정 / 1차 담당 면접관 / 2차 담당 면접관(항상 떵구) / 나이 / 성별 / 1차 면접기록메모(합/탈 포함) / 2차 면접 기록(합/탈 포함) / 변경 후 닉네임
목록은 "면접 대기자 / 합격자 / 탈락자" 3개 섹션으로 자동 분류됩니다.

## 팸원관리 탭
직책(패밀리장·관리자·패밀리원·신입·용병) / 닉네임 / ID / 가입일정 / 나이 / 성별 / 추천인 / 경고 기록(사유+상세 메모+사진 첨부, 여러 건 기록) / 메모 / 자료(사진)

- 목록 상단의 "직책 / 닉네임 / 나이 / 성별 / 경고 / 가입일정" 칸을 클릭하면 그 기준으로 정렬됩니다 (한 번 더 클릭하면 반대 순서). 값이 같은 사람끼리는 자동으로 닉네임 가나다순으로 2차 정렬됩니다. 직책은 패밀리장 > 관리자 > 패밀리원 > 신입 > 용병, 성별은 남성 > 여성 순서를 기준으로 합니다. 모바일에서는 표 헤더 대신 검색창 아래 정렬 드롭다운으로 같은 기능을 쓸 수 있습니다.
- 사진(자료)은 목록에서 바로 보이지 않고, "보기" 버튼을 눌러야 확대해서 볼 수 있습니다. 경고 기록에 첨부한 사진도 마찬가지입니다.
- 사진은 Firebase Storage 없이(추가 유료 플랜 필요 없이) 업로드 시 자동으로 크기를 줄여서 Firestore 문서 안에 직접 저장합니다. 아주 큰 원본 사진도 자동 압축되니 별도로 리사이즈하지 않고 올리셔도 됩니다.

## 1. Firebase 프로젝트 만들기

1. https://console.firebase.google.com 접속 후 구글 계정으로 로그인
2. "프로젝트 추가" → 이름 입력(예: `song-team-interview`) → 애널리틱스는 꺼도 됩니다 → 프로젝트 생성
3. 왼쪽 메뉴 **Build > Authentication** 클릭 → "시작하기" → 로그인 방법 탭에서 **익명(Anonymous)** 을 활성화

   (이 사이트는 이름+비밀번호를 직접 Firestore에 저장해서 관리하는 자체 로그인 방식을 씁니다. 여기서 켜는 "익명 로그인"은 Firestore 보안 규칙을 통과시키기 위한 최소한의 장치일 뿐, 실제 로그인 화면과는 무관합니다.)

4. 왼쪽 메뉴 **Build > Firestore Database** 클릭 → "데이터베이스 만들기" → 위치는 `asia-northeast3(서울)` 추천 → **프로덕션 모드**로 시작
5. 생성된 후 **규칙(Rules)** 탭에서 아래 내용으로 교체하고 "게시":

   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /{document=**} {
         allow read, write: if request.auth != null;
       }
     }
   }
   ```

6. 왼쪽 위 톱니바퀴 → **프로젝트 설정** → 아래로 스크롤 → "내 앱" → 웹 아이콘(`</>`) 클릭 → 앱 닉네임 아무거나 입력 → "앱 등록"
7. 화면에 나오는 `firebaseConfig` 값을 복사해서, 이 프로젝트의 `firebase-config.js` 파일 안의 값들을 그대로 교체하세요.

관리자 계정(윙윙/절미/하루/떵구)은 따로 만들 필요가 없습니다. 각자 사이트에 처음 접속해서 이름을 선택하면 "처음 로그인하시네요" 안내와 함께 비밀번호를 직접 정하게 됩니다.

## 2. GitHub Pages로 배포하기

1. GitHub에서 새 저장소(Repository) 생성 (Public이어도 되고 Private도 GitHub Pages 사용 가능한 플랜이면 무관)
2. 이 폴더의 파일 전체(`index.html`, `style.css`, `app.js`, `firebase-config.js`, `logo.png`)를 저장소에 업로드/푸시
3. 저장소 **Settings > Pages** 이동
4. "Build and deployment" → Source: **Deploy from a branch** 선택 → Branch: `main`, 폴더: `/(root)` 선택 → Save
5. 몇 분 후 `https://<사용자이름>.github.io/<저장소이름>/` 주소로 접속 가능

## 3. 사용법

- 로그인 화면에서 이름 선택 → 처음이면 비밀번호를 새로 정하고, 이후에는 정한 비밀번호로 로그인
- 비밀번호 입력창 오른쪽 👁 버튼으로 입력값을 눈으로 확인 가능
- 상단 "계정 관리" 버튼에서 4명의 현재 비밀번호를 눈표시로 확인하거나, 잊어버렸을 경우 "초기화"로 다음 로그인 때 새로 정하게 할 수 있음
- "+ 면접자 추가" 버튼으로 새 면접자 등록
- 1차 담당 면접관은 로그인한 사람 이름이 기본으로 채워지되, 원하는 사람으로 바꿔서 선택할 수 있습니다 (윙윙/절미/하루). 2차 담당 면접관은 항상 "떵구"로 고정됩니다
- 2차 면접 기록/합·탈 여부는 떵구로 로그인했을 때만 수정할 수 있고, 다른 관리자는 열람만 가능합니다 (화면(UI) 단에서만 제한하는 것이라, 완전한 서버 차원의 보안은 아닙니다 — 위 "보안 관련 유의사항" 참고)
- 목록에서 행을 클릭하면 상세 정보 확인/수정/삭제 가능
- 상단 검색창으로 닉네임/ID 검색
- 모든 변경 사항은 Firestore에 실시간 저장되며, 다른 관리자 화면에도 바로 반영됩니다
- 로그인 상태는 브라우저에 저장되어, 같은 기기/브라우저에서는 다시 들어와도 로그인이 유지됩니다 (로그아웃 버튼으로 해제)

## 참고 / 보안 관련 유의사항
- `firebase-config.js`에 들어가는 값은 비밀키가 아니라 공개되어도 되는 설정값입니다(Firebase 공식 안내).
- **비밀번호를 나중에 다시 확인할 수 있어야 한다는 요구사항 때문에, 이 사이트는 비밀번호를 Firestore의 `admins` 컬렉션에 평문(암호화하지 않은 그대로)으로 저장합니다.** Firestore 규칙은 "로그인(익명 포함) 상태"만 확인하기 때문에, 사이트 주소와 Firebase 설정값을 아는 사람이 개발자도구 등으로 직접 Firestore API를 호출하면 이론적으로 비밀번호/면접자 데이터를 볼 수 있습니다.
  - 내부 소규모 팀(4명)이 쓰는 비공개 관리 도구 용도로는 실용적인 선택이지만, 더 민감한 정보를 다룰 계획이라면 알려주세요 — Firebase Authentication + 서버(Cloud Functions) 기반으로 바꿔서 비밀번호를 안전하게 암호화하면서도 "관리자만 재설정 가능" 같은 방식으로 다시 설계해드릴 수 있습니다.
  - 저장소를 GitHub에 올릴 때 **Private 저장소**로 만드는 것을 추천합니다.
